# Совёнок

Интерактивный обход шахматной доски на HTML, CSS и JavaScript. Сборка — Vite; UI-фреймворков и серверной части нет.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```sh
npm install
npm run dev
```

Открыть адрес, который выведет Vite. `npm run build` создаёт статическую версию в `dist/`, `npm run preview` запускает её локально. Открывать исходный `index.html` через `file://` не нужно: приложение использует ES-модули и Web Worker.

## Соотношение и размеры

Пользователь задаёт коэффициенты **H₀ : D₀ : V₀** — по горизонтали, по диагонали и по вертикали — и размер поля **a × b** (от 1 до 50 клеток на сторону). Допустимы неотрицательные целые коэффициенты, но не три нуля. Коэффициенты используются как введены: они не сокращаются на общий делитель. Множитель x = (a × b − 1) / S должен быть положительным целым.

Старт всегда в левом нижнем углу (0, 0), финиш всегда в правом верхнем (a − 1, b − 1); интерфейс не позволяет выбрать другую точку. Проверка запускается автоматически с небольшой задержкой после ввода и по кнопке **«Проверить поле»**. При открытии страницы уже заполнены 1 : 2 : 4 и 3 × 5, поэтому ответ виден сразу.

Буквы **H**, **D**, **V** объясняются одной строкой над полями: горизонтальный, диагональный и вертикальный ход. Под полями размера показываются до четырёх минимальных проходимых досок для текущего соотношения. Нажатие на размер подставляет его и сразу строит маршрут. Если подобрать проходимую доску не удалось, блок говорит об этом прямо, не выдавая отсутствие примера за доказательство невозможности.

Маршрут проигрывается как видео: кнопка **play** двигает короля ход за ходом, стрелки и полоса прокрутки листают шаги вручную, скорость переключается от 0.5× до 8×. Если у поля немного обходов, над проигрыванием появляются стрелки «←» и «→» со счётчиком «Обход k из N»: соседние обходы в этом списке отличаются друг от друга на как можно меньшее число клеток. Список показывается, только когда полным перебором подтверждено, что обходов не больше тридцати; если их больше или перебор не успел завершиться, стрелки скрыты.

Вердикт показывается в панели параметров и на панели доски:

- **Да, поле можно пройти** — маршрут построен и независимо проверен; на доске показан путь, доступны шаги и воспроизведение.
- **Нет, поле пройти нельзя** — нарушено конкретное необходимое условие из валидатора; причина выводится полностью.
- **Обход не найден** — ни один обход из разрешённых блоков не дал результата. Это не значит, что обхода не существует; вердикт прямо это говорит.
- **Ошибка** — некорректное соотношение или размер поля.

Для нулевых коэффициентов поддерживаются, в частности, прямые обходы 1 × b и a × 1. Одними диагональными ходами посетить клетки обоих цветов нельзя.

## Математическая проверка

Пусть a — число столбцов, b — число строк. Клетки — вершины пути; один ход ведёт в соседнюю клетку, в том числе по диагонали. Начало — снизу слева (0, 0), конец — сверху справа (a − 1, b − 1). Пересечение линий между клетками разрешено, повторное посещение клетки — нет.

Для S = H₀ + D₀ + V₀ проверяем:

1. a, b — положительные целые; a × b > 1.
2. x = (a × b − 1) / S — положительное целое.
3. H = H₀x, D = D₀x, V = V₀x; H + D ≥ a − 1, V + D ≥ b − 1.
4. **(H + D) mod 2 = (a − 1) mod 2** и **(V + D) mod 2 = (b − 1) mod 2**.
5. (H + V) mod 2 = (a + b − 2) mod 2: 0 для одноцветных углов, 1 для разноцветных. Эта проверка следует из двух предыдущих, но оставлена явно.
6. При нечётном b необходимо H ≥ a − 1; при нечётном a необходимо V ≥ b − 1. Ограничения следуют из раскраски строк/столбцов по чётности и разности степеней вершин пути. Для чётной соответствующей стороны эти нижние границы не применяются.
7. Число ходов каждого типа не превосходит числа различных соседних пар этого типа; для посещения обоих цветов нужны ортогональные переходы.
8. При H = 0 и финише в верхнем правом углу необходимо **D ≥ (a − 1) × b / 2**. На 6 × 6 нужно хотя бы 15 диагоналей, поэтому 0 : 1 : 6 с квотами D = 5, V = 30 отклоняется. Симметрично, при V = 0 необходимо D ≥ (b − 1) × a / 2.
9. При H = 0 и **b, кратном 4**, этой оценки мало: двухстрочные полосы заканчивают естественный зигзаг в левом верхнем углу, и для финиша справа нужно пройти верхнюю полосу ещё раз. Требуется
   **D ≥ (a − 1) × (b / 2 + 1)**.
   Для 7 × 4 это D ≥ 6 × 3 = 18. Соотношение 0 : 4 : 5 даёт x = 27 / 9 = 3, то есть D = 12, V = 15, поэтому финиш в правом верхнем углу невозможен. Полный перебор подтверждает: при D = 12 существует ровно один маршрут, и он заканчивается в левом верхнем углу (0, 3); при D = 18, V = 9 (0 : 2 : 1) маршрут в правый верхний угол существует.
   Дополнительный проход относится именно к b ≡ 0 (mod 4), а не к любому чётному b: для 3 × 10 достаточно D = 10 (формула (a − 1)(b/2 + 1) дала бы 12), и полный перебор находит маршрут 0 : 10 : 19 в правый верхний угол. Для b ≡ 2 (mod 4) базовая оценка уже точна, поэтому в проверке дополнительное условие применяется только при b % 4 = 0. Для b = 6 (кратно 3) действует другой режим: минимум D = 6, а не 8.
10. При H = 0 и **чётном b** доска разбивается на b/2 полос по две строки. Полоса без горизонтальных ходов имеет единственный гамильтонов путь между нижним стартом в столбце s и верхним финишем в столбце t; он содержит |s − t| + 1 вертикальный ход. Соседние полосы соединяются диагональю, сдвигающей столбец на ±1. Складывая горизонтальные смещения вдоль всего маршрута, получаем **V ≥ a** (равносильно D ≤ a(b − 1) − 1). Поэтому квоты 5 × 4 с V = 3 или 4 × 4 с V = 2 отклоняются, даже если прежние оценки им не мешали. При V = a оценка достигается: для 3 × 4 это 0 : 8 : 3, для 5 × 4 — 0 : 14 : 5, для 7 × 4 — 0 : 20 : 7, для 5 × 6 — 0 : 24 : 5.
11. Для **квадрата 3 × 3** при D = 0 и финише в правом верхнем углу возможны только две раскладки: **H = 6, V = 2** или **H = 2, V = 6**, то есть соотношение **1 : 3**. Первый ход задаёт всё остальное: путь обязан обойти левый верхний угол, затем спуститься в нижнюю строку и подняться к правому верхнему углу. Поэтому квота 4 : 0 : 4 отклоняется, хотя прежние арифметические проверки её пропускали.
12. Равенство в оценке пункта 3 возможно только без диагоналей: **если H + D = a − 1 ровно, то все переходы между столбцами горизонтальны, D = 0**. При всего лишь a − 1 смене столбца король обязан пройти каждый столбец целиком одним вертикальным проходом и только потом перейти в следующий: вернуться в столбец позже уже не получится. Диагональный переход при этом начинается или заканчивается не в крайней клетке столбца, а из некрайней клетки король может пойти вверх или вниз, и часть клеток столбца останется непосещённой. Правило действует для любых прямоугольников, чётных и нечётных, при b ≥ 3; двухстрочные доски — настоящее исключение, потому что в столбце из двух клеток обе клетки крайние (3 × 2 с квотами 1 : 1 : 3 обходится). Полный перебор подтверждает правило на досках до 8 × 3 и 6 × 4. Симметрично, при a ≥ 3 равенство V + D = b − 1 возможно только с D = 0.
    Следствия: прямоугольник 5 × 3 требует хотя бы четырёх горизонтальных переходов — раскладки, у которых таких переходов всего два, обхода не дают; квадрат 4 × 4 с соотношением 2 : 1 : 12 не обходится — по горизонтали в сумме 3 хода = a − 1, но один из них диагональный, и этого недостаточно. Квота 3 : 0 : 12 при этом возможна: столбцовая змея.
13. Для доски **3 × 4 без диагональных ходов** финиш в верхнем правом углу достигается только двумя раскладками: **H = 2, V = 9** (столбцовая змея) и **H = 6, V = 5** (два зеркальных зигзага). Полный перебор находит ровно четыре маршрута, и никаких других соотношений без диагоналей для такого финиша не существует; например, 4 : 0 : 7 даёт маршруты, но все они заканчиваются в других клетках границы.

В условии чётности важно расстояние, а не количество столбцов: при чётном a расстояние a − 1 нечётное, поэтому H + D должно быть **нечётным**. Аналогично для строк. Из формул следует, что D нечётно только при двух чётных сторонах; в остальных случаях D чётно.

Эти условия **необходимы, но недостаточны**. Каждое доказанное дополнительное ограничение добавляется отдельным правилом; например, правило для 3 × 3 при D = 0 выше отсекает квоту 4 : 0 : 4. Независимый перебор маленьких досок входит в тесты; он также проверяет, что арифметические фильтры не отбрасывают реально существующие маршруты.

## Разрешённые блоки

`solver.js` собирает маршрут из HVHV, HDHD, VDVD, переходов HH, шнуровки и прямого завершающего прохода. Сначала расходуются лишние горизонтали через HVHV/HDHD, затем VDVD, после обычных полос — шнуровка. Произвольный поиск путей внутри полос не используется.

Для чётной высоты последние две строки полосы закрываются одним из блоков:

- **VDVH**: (0,0) → (0,1) → (1,0) → (1,1) → (2,1).
- **HDHH**: (0,0) → (1,0) → (0,1) → (1,1) → (2,1).

Последний ход входит в соседнюю полосу; если достигнут финиш, этот переход за границу доски не выполняется. Для чётной ширины одиночного последнего столбца нет: нужное число проходных полос обеспечивает конец сверху справа.

Вертикальная шнуровка — чередующийся диагональный подъём, вертикальный подъём, горизонтальный переход, вертикальный спуск и диагональный спуск по оставшимся клеткам. Вертикальные участки могут быть пустыми. Её горизонтальная копия **DDHHVHHDDV** получается транспонированием. Генератор пробует обе ориентации с обменом внутренних H/V-квот и возвращает путь в исходные координаты. Физические квоты при этом сохраняются.

Расчёт выполняется в `src/solver.worker.js`. Каждый найденный путь независимо проверяется: все клетки посещены, повторов и прыжков нет, концы правильные, квоты точные.

Дополнительно доступны блоки **VHVH, VHVV, VHVD, DHDH, DHDV**. Первые три хода заполняют блок 2 × 2, четвёртый входит в следующий блок. Для VHVD разрешён диагональный выход вверх или вниз; блоки отражаются по горизонтали и вертикали, а виртуальное транспонирование меняет H/V. На нечётных границах используются прямые участки из одной или двух клеток.

## Двухстрочные полосы

Для H = 0 и чётной высоты b `constructBands` режет доску на b/2 полос по две строки. В полосе разрешены только вертикальные и диагональные ходы; для каждой пары столбцов s (низ) и t (верх) её гамильтонов путь единствен и содержит |s − t| + 1 вертикальных ходов. Полосы сцепляются диагональю: следующая начинается в столбце t ± 1. Точная вертикальная квота набирается поиском по концам полос с запоминанием тупиков, а найденный путь проверяется общим `verifyRoute`.

Так строятся маршруты, которых не давали полосатые блоки: 3 × 4 (0 : 8 : 3), 5 × 4 (0 : 14 : 5), 7 × 4 (0 : 20 : 7), 5 × 6 (0 : 24 : 5), 6 × 6 (0 : 29 : 6). Если точную квоту полосами набрать не удалось, решатель по-прежнему возвращает «обход не найден»; конструкция не является полным решателем.

### Минимум вертикальных ходов

В минимальной раскладке двухстрочные проходы чередуются по двум схемам. Схема **(7)** ведёт к противоположному краю полосы: на полной ширине a она требует a вертикальных ходов и a − 1 диагональных. Схема **(9)** возвращает короля в столбец старта: на неё нужен 1 вертикальный ход, остальные — диагональные.

Пусть k = b / 2 — число полос. Тогда:

- при k = 1 возможна только схема (7), поэтому V = a и D = a − 1;
- при k = 2 и a ≥ 2 первая полоса даёт 1 вертикальный ход, вторая начинается со второго столбца и требует a − 1, итого V = a;
- при k ≥ 3 первая полоса даёт 1, каждая из k − 2 средних — по 2, последняя — 1 + a − 2(k − 1); сумма
  `1 + 2(k − 2) + 1 + a − 2(k − 1) = a`.

Например, для 6 × 8 (k = 4) получается 1 + 2 + 2 + 1 = 6, а для 8 × 8 — 1 + 2 + 2 + 3 = 8: две дополнительные колонки добавляют два хода схемы (7) и два вертикальных хода, но V по-прежнему равно a.

Формула предполагает невырожденный последний проход, то есть a ≥ b − 2. При a < b − 2 минимум больше a; например, полный перебор для 3 × 6 даёт минимум V = 5 при a = 3. Поэтому проверка оставляет универсальную нижнюю границу V ≥ a, а точную квоту в узких случаях подбирает поиск по концам полос.

## Двухпрямоугольная раскладка

Этот способ оставлен в решателе как внутренняя возможность и не подключён к интерфейсу с фиксированным финишем.

Если финиш лежит на кромке, доска режется по его столбцу (для левой и правой кромок — после транспонирования). Левый прямоугольник проходится из (0, 0) в свой дальний угол на строке перехода, маршрут шагает в правый прямоугольник, и тот заканчивается в углу клетки финиша. Обе части собираются из тех же разрешённых блоков, поэтому маршрут идёт полосами и пересекает границу раздела **один раз**, а не змеится через неё.

Например, для доски 12 × 8 с квотами 2 : 1 : 2 и финишем (7, 7) левый прямоугольник 7 × 8 заканчивается в (6, 0), шаг идёт в (7, 0), правый прямоугольник 5 × 8 заканчивается в (7, 7). Счётчики при этом точные: H = 38, D = 19, V = 38.

Раскладка применяется, только если квоты делятся между прямоугольниками без остатка; иначе используется прежний поиск по блокам. Ограничение снизу: каждая часть должна быть не уже двух столбцов.

## Фиксированный финиш

Интерфейс не позволяет выбирать точку финиша: она всегда в правом верхнем углу. Сначала `solveBoard` строит полосатый маршрут. Если он не найден, `solveCorner` запускает поиск по разрешённым блокам и берёт только маршрут, заканчивающийся в правом верхнем углу. Например, для 3 × 7 с соотношением 1 : 1 : 3 полосатая конструкция не срабатывает, а блочный поиск даёт проверенный обход.

Подсказки работают в обе стороны: для введённого соотношения `findCornerBoardSuggestions` предлагает проходимые доски, а для введённой доски `findCornerRatioSuggestions` предлагает небольшие соотношения, для которых уже построен проверенный маршрут в правый верхний угол. Оба списка — удобство, а не доказательство полноты: пустой список означает «пока не подобрано».

Функции `findSplitRoute`, `findFinishChoices`, `findBoardChoices` и `getFinishCells` остаются в `solver.js` и покрыты тестами как отдельная возможность, но интерфейс их не вызывает. Они пригодятся, когда математика произвольных финишей будет рассматриваться отдельно.

**Конструктор блоков не является полным решателем общей задачи.** Вердикт «обход не найден» означает только, что разрешённые конструкции не дали результата; он не выдаётся за доказательство невозможности. Исключение — вердикт «поле пройти нельзя»: он выводится только при нарушении необходимого условия из валидатора.

## Проверка

```sh
npm test
npm run build
```

Тесты проверяют чётность относительно расстояния, нулевые и ошибочные коэффициенты, x ≥ 1, все допустимые размеры для соотношения 1 : 2 : 4 до 50 × 50, новые блоки и их порядок, разные соотношения, транспонирование, минимальную площадь и tie-break, прямые обходы, независимый полный перебор маленьких досок, блочный запасной поиск для фиксированного верхнего правого угла, дополнительную оценку для H = 0 при b, кратном 4 (с регрессией для b ≡ 2 mod 4, b = 6, 8 и 10), нижнюю оценку V ≥ a для двухстрочных полос, формулы минимума для проходов (7) и (9) и построенные ими маршруты, правило 1 : 3 для квадрата 3 × 3 без диагоналей, правило равенства H + D = a − 1 (все переходы горизонтальны) с исключением для двухстрочных досок, правило 2 : 9 и 6 : 5 для доски 3 × 4 без диагоналей, подбор проверенных досок-примеров, обратный подбор соотношений для заданной доски, полное перечисление обходов для перелистывания и обнаружение неверных маршрутов.

В `.npmrc` закреплён публичный реестр `https://registry.npmjs.org/`, чтобы установка не зависела от локального npm-окружения.

Каждый push в `main` запускает `.github/workflows/deploy.yml`: установка через `npm ci`, тесты, сборка и публикация `dist` в GitHub Pages. Workflow также можно запустить вручную в GitHub Actions.

В `vite.config.js` задан `base: "./"`: HTML, CSS, favicon и Web Worker используют относительные пути и работают как в корне локального сервера, так и в `/sovenok/` на Pages. В репозиторий отправляются исходники и lock-файл; `node_modules` и `dist` исключены.
